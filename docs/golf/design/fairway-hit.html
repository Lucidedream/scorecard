Fairway Hit

One tap on the tee shot of a par 4 or par 5 to record that it found the fairway. It shows as a small check icon next to the field — not a letter, because “F” reads as false. It changes no stroke, no total, and no penalty. The button that opens the sheet is renamed Mark, and it no longer opens on the Putts field. Alongside it, the round now derives greens in regulation from data it already has — and both “in regulation” figures land in trends and the phone report.

§ 1What it is

A positive marker on the same sheet the penalties live on

Today Confirm (while Power cycles the field) opens a small sheet with two choices — Hazard and OB. Each one adds a shot to the focused field and adds penalty strokes. Fairway Hit joins that sheet as a third choice, but it is a different kind of thing:

  • No shot is added. The tee shot was already counted in the score-zone field (or by the par pre-seed). Fairway Hit only annotates it.
  • No penalty, no total change. strokes, THRU, HOLE, TOTAL and the PENALTY +N band are all untouched.
  • It is a per-hole yes/no, not a counter. You either hit the fairway off the tee or you didn't — there is nothing to add twice.

Why it belongs on that sheet and not its own button

The X4 has four front buttons and they are all spoken for (§13.2). The Mark sheet is already the place you go to say something about the shot you just played that the three counters can't express. “It found the fairway” is one more thing of exactly that shape.

The name

“Penalty” is now wrong on the footer and wrong as the sheet title. Mark replaces it in both places — footer cell 2 and the sheet title.

The marker is an icon, not a letter

A lone F beside H and OB reads as a grade or a false — the opposite of what a fairway hit is. An icon breaks it out of the penalty-letter set entirely: same slot, but visibly a different kind of thing — the good kind. The mock uses circle-check (Lucide); it also closes a nice loop with the picker's checkbox. Alternatives in §3.

Putts loses Hazard and OB

You cannot hit a hazard or go out of bounds with a putt. The Mark sheet had those two rows on every field, including Putts; it now does not open at all while Putts is focused, and footer cell 2 goes blank there. Existing rounds that somehow carry a Putts marker still display and can still be removed with Down — only the entry path is closed.

§ 2When the option appears

Fairway Hit shows only where it means something

The sheet already attaches to whichever field is focused. Fairway Hit is added as a third row when the focused field is To Score Zone and either the hole is a par 4 / 5, or the course has no par data at all. Everywhere else the sheet is unchanged — Hazard and OB — and on Putts it doesn't open.

Par 3 vs. par-free

On a par-rated course the row is left off par 3s — the tee shot targets the green, and “fairway hit” isn't a par-3 stat. On a par-free course the device can't tell a 3 from a 5, so it offers the row everywhere on the score-zone field and trusts you not to tick it on a one-shotter. Par-free rounds are then excluded from the FIR percentage in trends (no reliable denominator), but the raw count still shows in that round's report.

The flag and a hazard can share the field

A par 5 tee shot can find the fairway and a later shot on that same field can find water. The row then reads check + H: check first (it's the good news and it's the tee shot), then the penalty letters in the order they happened. Down still peels penalty markers off that field per §12.4; it does not touch the fairway bit — the checkbox is the only thing that clears that (§8).

§ 5Storage & rules

A dedicated per-hole flag, not a fourth penalty kind

The first instinct was to add kind = 2 to the penalty nibble. That doesn't work: bit 3 of the nibble is the corrupt-event sentinel (0x08) — both the packer's reserved bit and the JSON reader's “unreadable” marker. A fairway kind that set it would be indistinguishable from a damaged penalty, and an older build reading the round would show a phantom penalty and inflate the count. So Fairway Hit gets its own storage. 

struct GolfPlayerScore {
  uint8_t putts[18];
  uint8_t in100[18];
  uint8_t out100[18];
  uint8_t penaltyCount[18];
  uint8_t penaltyEvents[18][4];
  uint8_t fairwayHit[3];        // NEW -- bit N = hole N tee shot found the fairway
};

+3 bytes per player, +12 to GolfRound (906 → ~918). Packed as a bitmask for the same reason the penalty nibbles are — it is repeated per player and serialized on every flush. All three static_asserts move with it.

The interaction is a toggle

  • The Fairway Hit row shows a checkbox reflecting fairwayHit for the current hole.
  • Confirm flips that one bit — sets it if clear, clears it if set. Seeding (§13.1) runs first, exactly as every mutation path must.
  • No counter moves. strokes, penaltyStrokes, THRU, HOLE, TOTAL are all untouched by definition — the bit isn't in any of their formulas.
  • The checkbox is the only way to clear it — Down stays strictly about strokes and penalty markers.

Icon asset

One Lucide icon (circle-check), generated into golfTileIcons.h at 16 and 24 px — 16 for the field marker, 24 for the sheet's tag column. Add one line to golfTileIcons.manifest and regenerate; the fork touches no upstream icon file (§25.4). The freeink::Icon struct carries an opticalCenterY, so aligning it to the field number is one call, no magic offset.

Round file — v4 → v5

The round file and state.json are already at "v": 4. Bump to 5. Each player object gains "fairways": an 18-element 0/1 array, written zero-filled for disabled slots like the other per-hole arrays. v4, v3 and v2 files still read — a v4 round simply has no fairway data and every hole loads as not-hit. v1 stays rejected.

index.csv — four new columns

...,hazards,obs,fairways,fairwayHoles,gir,girHoles,file
  • fairways / fairwayHoles — FIR numerator and denominator (holes with the bit set / entered par 4-5 holes).
  • gir / girHoles — GIR numerator and denominator (entered holes that met regulation / entered holes with a known par). Both are derived at archive time from data already in the round — see §6.

The header changes, so the §12.7 guarded migration applies: write index.csv.new with the v5 header and every existing row widened with four empty fields, verify the row count, then the two renames. An empty field means not recorded — the round predates the feature — and trends must exclude it, never read it as zero. A full index rebuild (the recovery path already opens every round file) backfills gir/girHoles for old rounds, since GIR needs no stored input.

§ 6The two “in regulation” figures

Fairways in regulation, and greens in regulation

A fairway hit is worth capturing on its own, but the reason golfers track it is the pair it forms with greens in regulation. GIR needs no new input — the three counters plus par already contain it — so it comes along for free.

Green in regulation — the rule

You reach the green “in regulation” when the strokes taken to get there are at least two under par: 1 on a par 3, 2 on a par 4, 3 on a par 5. 

strokesToGreen = holeScore - putts          // holeScore = in100 + out100 + penaltyStrokes
GIR            = strokesToGreen <= par - 2   // hole entered, par 3-5 known

putts is the count of strokes on the green, so subtracting it from the hole score leaves exactly the strokes it took to arrive — tee shot, recoveries, penalty drops and all. A chip-in counts (0 putts, score already ≤ par-2); a missed green that scrambles to par does not. Par-free holes have no GIR.

Fairway in regulation

FIR is just the fairway-hit bit, counted over the par 4-5 holes played. It is only offered on those holes (or every hole on a par-free course, which is then excluded from the percentage). Nothing derived — it is the one thing the golfer actually enters.

In trends

girPercentTenths = 1000 x sum(gir)      / sum(girHoles)
firPercentTenths = 1000 x sum(fairways) / sum(fairwayHoles)
  both folded over index rows where the denominator was recorded and > 0
  both gated on >= 2 such rounds, mirroring enoughMixRounds()

Shown as two more percentages next to the existing long / short / putting / penalty mix. GolfTrendStats gains girPercentTenths, firPercentTenths and a regulationRounds count for the gate.

In the phone report

  • Per hole (JSON / CSV / HTML): fairway (true/ false/null when not applicable) and gir (true/false/null when par-free).
  • Round summary: fairways_hit / fairway_holes / fir_pct, and greens_in_reg / gir_holes / gir_pct.
  • FIR fields sit behind a fairwaysRecorded gate (they need the stored bit). GIR is emitted for any round with par data, including old ones — it is computed, not stored.
§ 7Footer cleanup

The sheet footer becomes two cells for real

§13.3 already says the picker footer is two cells: BACK and CONFIRM. The code passes empty labels for cells 3 and 4, but the theme still paints the right-hand hint group as an empty rounded pill — the “prev and next button which is not enabled.” This removes it: a two-cell footer mode that draws only the left group, so the sheet ends at CONFIRM with nothing dead to its right.

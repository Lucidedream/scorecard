§ 1The page unit

The content already decided the design

Slope Strategy is not prose — it is nine named conditions, each with four or five bullets. On the course you are not reading it, you are looking one thing up: you are on a downhill lie with the ball above your feet and you want that section.

So a note pages by section, one per screen, rather than by arbitrary screenfuls of scrolled text. Nine taps of ▸ walks the whole note, every screen is a complete thought, and no bullet is ever split across a page break.

One thing in your text will not render

I checked the font's glyph table: → (U+2192) is missing. Your note uses it eight times. Bullets (•), em dashes and curly apostrophes are all present — only the arrow is absent, and it would draw as a gap or a box.

The stored file therefore says "expect fade, so aim left" instead of "→ aim left". It reads the same and needs no font work. Adding U+2192 would mean regenerating every font, which is a large change for one glyph.

§ 2The screens

Three levels, two entry points

Main menu → Tips and Round menu → Tips reach the same two screens, so there is one implementation and one thing to learn.

§ 2bMain menu

The menu becomes four tiles

§22.1 justified the horizontal tiles partly on the set being fixed at three. That is no longer true, so the reasoning is worth restating: the point was never the number, it was that the set is small, fixed, and every item should be visible at once. Four still satisfies that.

Four tiles across 480 px leaves 118 px each after borders. Every label clears it comfortably — the longest, "New round", needs about 77 px and still wraps to two lines as it does today.

Where the ceiling actually is

Four fits well; a fifth would leave 94 px per tile and start forcing labels to wrap awkwardly. If a fifth destination is ever wanted, that is the moment to reconsider the shape — a 2×2 grid, or tiles that scroll — rather than squeezing. Worth knowing now so the decision is deliberate later.

§ 3The file format

Plain text, because you are the author

Tips are yours. You should be able to write one in any editor, drop it on the card, and see it — no schema, no build step, no on-device editor for me to design and you to fight with on seven buttons.

The rules, all four of them

  1. The first line is the note's title, shown in the list.
  2. A blank line starts a new section, and each section is one screen.
  3. The first line of a section is its heading.
  4. Lines beginning • or - are bullets; anything else is a plain paragraph line.
Slope Strategy

Ball below feet - fade bias
• Ball centered
• Wider stance, more knee flex
• Stay low through the swing
• Clubface points right; expect fade, so aim left
• Prioritize posture and balance

Ball above feet - draw bias
• Ball centered; choke down
...

Your note is already written to this format at docs/golf/examples/tips/slope-strategy.txt — 2,152 bytes, 37 bullets, 9 sections. Copy it to /golf/tips/ on the card.

Two limits worth stating up front

A section must fit one screen. If a section has too many bullets to fit, the note screen shows what fits and marks the overflow rather than silently dropping it — a note that quietly loses a line is worse than one that admits it.

Notes stream, they do not all load. Only the current section is held in RAM. On 380 KB the app cannot assume a tips folder is small, and the round in progress must never lose memory to a note you are reading.

Mockups render at true 480 × 800 in pure black and white. The Slope Strategy text is the owner's own, with → replaced by "so" because that glyph is absent from the device fonts.

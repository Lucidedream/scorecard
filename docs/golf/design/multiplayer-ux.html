Ask how many, then get out of the way

§ 1The header

It inherits the book reader's header, and that was never right

The golf screens size their header from metrics.headerHeight — the same metric the e-reader uses for a book's title bar. That metric is not a constant:

Golf header height, by whichever theme the reader happens to be on
ThemeheaderHeightEffect on the scorecard
Classic45 pxAbout right
RoundedRaff45 pxAbout right
Lyra84 pxNearly double — the band dominates

A book header wants height: it carries a title, progress, and page counts. A scorecard header carries a name, a course, and the time. Borrowing the book metric means the scorecard's chrome changes size when you change reading themes, which is a coupling nobody asked for.

The fix

Golf screens get their own fixed header height — 46 px, the compact status strip from the earlier design, sized so the band is the battery indicator plus its padding and nothing more. It stops tracking the reading theme entirely.

§ 2How many players

A solo round should cost two presses

Most rounds are one player. The count step must not tax that case to serve the rare foursome, so it opens on 1 with Confirm already the right answer.

The roster screen is skipped entirely for a solo round. One player means one name and one tee, both already defaulted, so there is nothing on that screen to decide. Confirm on the count goes straight to the first hole.

Why the names are numbered from 2

The round already ships defaults of Noah, Player B, Player C, Player D. Letters and numbers read as two different schemes when slot 1 is a name, so the letters become Player 2 / 3 / 4 — matching the row index beside them. Slot 1 keeps its name, because it is a person, not a slot.

One thing this design deliberately does not do

There is no "add player" row on the roster. The count is chosen once, on its own screen, and the roster only reflects it. Two places to change the same number is how the home screen's off-by-one bugs happened — one owner for a value, always.

§ 3The totals row

Three numbers in a row built for two

The totals band splits into three equal cells — Thru, Score, To par — each a third of 480 px minus padding. At a 12 pt bold face, a two-digit score and a signed to-par run out of room and collide.

Dropping Score is the right cut, because to-par already contains it: with par known, score = par-so-far + to-par. Thru and to-par together are what a golfer actually says out loud — "seven through, six over."

What the band shows
CourseCellsReason
Has parThru · To parTwo cells, no collision; score is implied
Par-freeThru · ScoreTo par cannot exist, so score returns to fill the slot

The par-free case is not an afterthought

The Template course has no par, and today the third cell simply renders empty. If we drop Score outright, a par-free round would show Thru and a blank — losing the only running total it has. So the rule is positional: the second cell is to-par when par exists and score when it does not. Never both, never blank.

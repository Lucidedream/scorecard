## Verified by reading

* **History is genuinely index-only.** `GolfRoundSummaryActivity` contains zero
  references to JSON, `RoundArchive`, or `.json`. The worker went further than asked and
  never even existence-checks the round file, so a deleted archive cannot break the list
  — a stronger guarantee than the contract required.
* **The ring buffer is right.** `GolfHistoryReader` holds a fixed
  `GolfHistoryEntry[50]` plus one line buffer, no heap. `newest(i)` indexes
  `(nextEntry + CAPACITY - 1 - i) % CAPACITY`, which is the correct newest-first
  reversal, and `overflowed()` reports `validRows > CAPACITY` rather than silently
  truncating.
* **It is a streaming reader**, not the single-pass read I specified: `feed()` /
  `finish()` accept arbitrary chunk boundaries. Better than the brief, and it means a
  large `index.csv` never lands in RAM whole.
* **The par-free path is real.** `rows = hasPar ? 6 : 5` with a row-index shift, so the
  Par row and every to-par figure vanish rather than printing zeros. Reachable today —
  Sanyang ships par-free after v2.1.
* **Unentered holes render `GolfStrings::DOT`**, never `0`, at all three sites
  (cell, nine-total, grand total).

## Interpretation accepted

For 18 holes the Front tab carries holes 1–9 + OUT + TOTAL, the Back tab 10–18 + IN +
TOTAL. That is the conventional paper-scorecard layout, and duplicating all three
aggregate columns on both tabs would further compress an already dense 480 px table.
Correct call.

### The shape of the fix

v2.5 moved the commit from the fourth press to the third and let Power cycle the field.
v2.6 then replaced press-counting with position entirely:

```cpp
GolfConfirmAction golfConfirmPress(GolfField focusedField, bool holeLogged, bool hasValuesToCommit) {
  if (focusedField != GolfField::Out100) return GolfConfirmAction::CycleFocus;
  if (!holeLogged && hasValuesToCommit) return GolfConfirmAction::CommitAndAdvance;
  return GolfConfirmAction::AdvanceWithoutCommit;
}
```

`GolfConfirmState`, `pressesSinceReset`, `golfConfirmReset`, and all three reset
conditions are gone. The function is now a pure function of its inputs with no memory,
so the stale-count hazard that the mutation-reset existed to prevent **cannot occur by
construction** rather than being guarded against.

The binary shrank by 48 bytes, which is the expected sign that the state really was
removed rather than relocated.

### Note on the original off-by-one

v2.5's rename of `GOLF_CONFIRM_LAP` to `GOLF_SCORING_FIELD_COUNT` is worth recording:
the off-by-one existed *because* the old name encoded a threshold rather than a count,
which made the wrong comparison read as plausible. Naming a constant after what it
counts, not after how it is compared, would have prevented it.

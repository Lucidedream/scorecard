## What was correct

* `GolfRound` matches CONTRACTS §1 field-for-field. `sizeof == 164` verified by hand:
  40 + 12 + 2 + 1 + 1 + 18 + 36 + 18 + 18 + 18, struct align 2. The `static_assert`
  pins it.
* **Entered-holes-only sums** — the highest-severity requirement — hold everywhere.
  `isEntered()` guards every accumulation and `holesInRound()` clamps to both
  `holeCount` and `MAX_HOLES`.
* The §2.1 bitmask is implemented correctly, including a property I checked
  specifically: `blockedByFloor()` is unreachable with an empty mask, because
  `strokes >= 1` and `shortShots == 0` cannot satisfy the block condition. So
  `blocked == true` always carries a non-zero mask.
* Clamp-versus-block is correctly distinguished. `clamped()` returns
  `{false, false, 0, false}`, so an ordinary floor never makes the UI flash.
* Auto-bump is right, including the corner where `strokes` is at the 99 ceiling: the
  short counter is then refused rather than allowed to break the invariant.
* `golfWorstHoles` insertion sort is correct on the eviction path, and ties preserve
  hole order — so a screen will not reshuffle between repaints.
* Test coverage maps onto the contract's behaviour table rather than the
  implementation, including the exact joint-block case that was demanded
  (`strokes=5, putts=2, in100=3`, both bits asserted, round state unchanged).

## The defect (returned as M0.1)

`[env:golf]` declares `extends = default`. PlatformIO's `extends` takes **section**
names, and no `[default]` section exists — the sections are `[platformio]`,
`[crosspoint]`, `[base]`, `[firmware_tuned]`, and the `[env:*]` envs. The env therefore
inherits no platform, board, or framework:

```text
Processing golf ()
UndefinedEnvPlatformError: Please specify platform for 'golf' environment
```

The fix mirrors `[env:default]`: `extends = base, firmware_tuned`. The adjacent
`${env:default.build_flags}` interpolation is correct and stays.

**This is partly my fault.** After the toolchain escalation I explicitly told the worker
the firmware gates were mine to verify, so it never ran the one command that would have
caught this. Directing a worker away from a gate means owning what the gate would have
found.

## Contract defects the worker found

Both were real, and both were mine:

1. **§2 named one blocking field** while `putts` and `in100` can hold the floor jointly.
   No priority order is correct, because reducing either unblocks the decrement. Fixed

   clamp-versus-block gap the worker had not asked about.
2. **M0 required registration in `test/CMakeLists.txt` while acceptance allowed one
   upstream file.** Contradictory. `test/CMakeLists.txt` is now a sanctioned fourth
   touchpoint.
3. The worker also flagged that my required marker comment plus two registrations is
   **three** lines against a stated 2-line budget. Correct; budget fixed to 3.

## Contract gap the architect found

The §2 invariant is airtight *through the mutation API* but not against a `GolfRound`
populated from outside. A file with `strokes = 0, putts = 1` is already invalid;
incrementing putts then yields `putts = 2, strokes = 1`. The rules layer is entitled to
assume a valid starting state, so this is not an M0 defect — M0 has no file I/O. It is
now CONTRACTS §9, an explicit M1 loader requirement with mandated repair ordering and
logging.

## Environment

Three stacked problems, all architect-owned, all now fixed except the last:

1. **Disk exhaustion** (the worker's diagnosis) corrupted the first toolchain install.
   Freed ~5 GB, partly by deleting a 2.2 GB broken install of my own making.
2. **pioarduino `install_tool()` chicken-and-egg** — `_check_tool_status()` looks for
   `tools.json`/`.piopm` inside a package directory that does not exist yet, so neither
   install branch fires and it silently returns success. Fixed with a *project*-scoped
   `pio pkg install -e default`.
3. **Nested archive layout** put binaries at `packages/toolchain-riscv32-esp/riscv32-esp-elf/bin/`
   while the platform resolves `packages/toolchain-riscv32-esp/bin/`. Flattened,
   preserving `.piopm`.
4. **Unfixed:** the macOS Command Line Tools SDK is broken — bare `clang++` cannot find
   `<cstddef>` even with an explicit `-isysroot`. Host tests therefore require
   `/opt/homebrew/opt/llvm/bin` on PATH, and `cmake` requires
   `$HOME/.platformio/packages/tool-cmake/bin`. **The documented
   `pio run -t unit-tests` gate cannot pass on this machine as written.** Recorded
   rather than worked around; a wrapper or a documented PATH prefix should be decided
   before M1.

### The `CROSSPOINT_VERSION` question

Fixing `extends` exposed a second layer: `scripts/git_branch.py` injects
`CROSSPOINT_VERSION` only for the `default` and `sticky` envs, while
`lib/hal/HalSystem.cpp:137` consumes that macro, so `env:golf` compiled and then failed
to link its panic-info string.

The worker offered two options — add `golf` to the script's tuple (a fifth touched
upstream file), or hardcode a version. **Both were rejected.** `[env:slim]`
(platformio.ini:202) and `[env:x4pro]` (:265) already establish the idiom for variant
environments: name your own version in `build_flags`. `env:golf` now does the same with
a `-golf` suffix, at zero new touchpoints.

This established the standing tie-breaker now recorded in ARCHITECTURE.md §2: *when
upstream already provides an idiom that avoids touching a new file, use the idiom.* It
exists because this was the second request in one milestone to widen the fork surface,
and each such request is individually defensible while collectively defeating the rule.

Accepted cost: a golf panic dump names the variant but not the exact commit, exactly as
`slim` already does. Revisit only if it actually bites during hardware debugging.

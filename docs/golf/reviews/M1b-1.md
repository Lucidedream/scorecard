## Verified by reading

* **Marker precedence is correct.** `fromJson` checks `archivedAs` before parsing any
  other field. This was the worker's own finding and it is the important one: had the
  score arrays been validated first, corruption in them would fail the load, hide the
  marker, and cause a second archive or a resume of a finished round. Now ratified into
  §6.1, which previously left the ordering implicit.
* **The stroke-index permutation check is sound.** A `uint32_t` bitmask of seen values
  plus a `1..holeCount` range check makes "exactly `holeCount` entries, all in range, no
  duplicates" a permutation by pigeonhole — no sort, no allocation.
* **Validation catches a case that was never specified:** `yards` or `si` carrying data
  while flagged absent (`UnexpectedOptionalData`). That is exactly the shape a
  half-finished hand-edit produces.
* Error reporting carries kind, field, hole, value, and expected — rich enough for the
  actionable log line §5.1 requires.
* `archive()` is now idempotent: `isArchived()` short-circuits to a clean clear, and
  `markArchivedAs()` writes the commit marker before deletion.

## Findings accepted without change

* **"Missing" stroke index is not separately representable.** In a fixed array whose
  entries must be `1..holeCount`, a missing value necessarily shows up as a duplicate or
  an out-of-range value. A distinct error kind would restate another diagnosis. Correct.
* **Overflow is keyed on JSON candidates present**, not on courses that validate. The
  conservative reading, and the right one — reporting only valid courses would let a
  directory of broken files look empty rather than broken.
* **`archivedAs` length** bounded by the round-filename buffer; empty or oversized
  markers rejected rather than honoured.

## Carried into M1b-2 (my omission, not a defect)

**Enumeration order was unspecified**, so results preserve raw SD directory order.
Stable, but arbitrary — a course picker whose rows appear in an unexplained sequence
reads as broken. Now CONTRACTS §10: alphabetical by `name`, case-insensitive, in-place
insertion sort over at most 32 entries, no heap. The worker was never asked to order
results.

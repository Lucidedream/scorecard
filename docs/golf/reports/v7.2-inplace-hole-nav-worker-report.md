# v7.2 in-place hole navigation worker report

## Implementation

The hole sheet, its state, render/input handlers, geometry, and sheet-only tests were
removed. A tap on the hole band is inert. A horizontal swipe beginning in the hole band
steps one hole without wrapping and preserves the player; swiping the existing nine strip
changes only its viewed page (`src/activities/golf/GolfScoringActivity.cpp:615-645`).
Tapping a valid strip cell jumps through the retained rules wrapper; a current-hole tap
and an empty-cell tap are inert (`src/activities/golf/GolfScoringActivity.cpp:711-718`).
The wrapper retains archive rejection, locked rules mutation/reset, dirty marking, immediate
flush, and update, with no seeding (`src/activities/golf/GolfScoringActivity.cpp:320-334`).

`nineStripPage` follows the round on entry and on all turn changes through
`resetTurnState()` (`src/activities/golf/GolfScoringActivity.cpp:194-201`). Both the jump
wrapper and PREV/NEXT/Power turn traversal call that reset. The original-height strip
uses the same score-cell renderer and inversion rule, with its first hole selected from
the viewed page on touch boards (`src/activities/golf/GolfScoringActivity.cpp:984-1026`).
Non-touch rendering continues to derive the page from the round.

The constexpr helpers operate on the existing strip rect: nine equal partitions with
deterministic integer boundaries, hole hit-testing, page count, and page clamp
(`src/activities/golf/GolfUiLayout.h:237-261`). New host tests cover cell centres and both
horizontal boundaries, all four outside edges, every hole count from zero through 18,
empty cells, invalid pages, and clamping without wrap
(`test/golf_layout/test_golf_layout.cpp:201-244`). Existing counter-zone and
`golfJumpToHole` tests remain.

## Contact-start latch

The activity stores a `Point` and a validity boolean. On each touch-board loop it queries
`isScreenTouchHeld()` and records the first observed point only when the latch is invalid.
It handles the complete scoring frame, then clears on `wasScreenTouchReleased()` or when
a second held query reports no eligible contact
(`src/activities/golf/GolfScoringActivity.cpp:598-613`). The second query is intentional:
the frame may consume a long-press and suppress the contact while dispatching input.
The latch also resets on entry (`src/activities/golf/GolfScoringActivity.cpp:138`).

This uses only public `MappedInputManager` queries. Its held query converts the SDK's
live coordinates into logical screen coordinates without the tap-slop gate
(`src/MappedInputManager.cpp:184-191`). Its down query is a tap candidate delayed by
90 ms (`src/MappedInputManager.cpp:130,163-170`), so it is not used to capture a quick
swipe. The SDK held query rejects suppressed and multi-contact sequences
(`freeink-sdk/libs/hardware/InputManager/src/InputManager.cpp:654-660`), and release can
be hidden for suppressed single contacts (`:587-592`); the absence fallback clears these.

Back is handled before the swipe query (`src/activities/golf/GolfScoringActivity.cpp:658-666`).
Every recognized swipe returns before tap or counter dispatch, including vertical swipes,
swipes with no valid start, and swipes originating outside the navigation bands. While
the mark picker is open, its existing input handler retains exclusive ownership of input.

The public API gives the first point observed by the activity, not guaranteed historical
touch-down coordinates. If a very short contact begins and ends entirely between activity
frames, no start is latched and its swipe is ignored. If the first observation arrives after
the finger has crossed a band boundary, classification follows that observed position;
device verification must exercise quick swipes near boundaries and during SD/display work.
Once latched, subsequent movement cannot reclassify the origin. Missing/suppressed contact
and release both clear the latch, so the next observed contact starts afresh.

## Acceptance and scope

- §39.5 builds, host tests, formatting, and scope checks: results below.
- Removed-sheet scan over `src` and `test` is empty; the historical specifications and
  reports remain as documentation.
- §38.1 classifier and the select/count block are unchanged; the new swipe return prevents
  swipes on counter rows from reaching that block. The existing counter tests pass.
- Mark picker rendering and input, including bare Power confirmation, are unchanged.
  Only its obsolete exclusion of the removed sheet was deleted.
- `hasTouch()` gates the new latch and swipe query; `FooterInput` gates body taps, and the
  non-touch strip uses the current round's page. No upstream file or translation was edited.
- No allocation or new user-facing text was introduced. State consists of one page byte,
  one validity boolean, and a four-byte point, embedded in the existing activity. New
  geometry is constexpr and local records stay below 256 bytes.

# v7.1 — Touch scoring: tap-to-count and the hole strip

**Worker task brief.** `docs/golf/CONTRACTS-V2.md` §38 is the specification and is
authoritative; read §37 and §38 in full first. Root `AGENTS.md` / `CLAUDE.md` govern coding
standards. You do not amend the contract: if it is wrong or impossible, stop and ask the
coordinator.

## Goal

Two owner-requested touch features on the Scoring screen, X4 Pro only in effect:
tap the selected counter row's left/right third to count down/up (§38.1), and tap the
hole number to open a swipeable strip of holes and jump to one (§38.2).

Build on the existing touch work: `golfui::FooterInput` (`GolfUiLayout.h`), the counter
tap-to-focus block and the mark-sheet tap handling in
`src/activities/golf/GolfScoringActivity.cpp`.

## Deliverables

1. §38.1 tap-to-count, with the constexpr zone classifier and its host tests.
2. §38.2 hole strip: `golfJumpToHole` in `src/golf/GolfRules.{h,cpp}` with host tests
   (`test/golf_rules`), constexpr strip geometry + hit-test with host tests
   (`test/golf_layout`), and the sheet in `GolfScoringActivity`.
3. Report at `docs/golf/reports/v7.1-touch-scoring-worker-report.md`: what was built with
   file:line references, how each §38.3 acceptance item was verified, exact commands and
   results, firmware sizes, and anything not verifiable without the device.

## Hard constraints

* Runtime-gated on `mappedInput.hasTouch()`; behaviour without touch is unchanged.
* No upstream file edits except Scorecard keys in `lib/I18n/translations/*.yaml` if a new
  string is truly needed (prefer existing keys). Never edit generated I18n headers.
* No new heap allocation; locals under 256 bytes; UI strings through `tr()`.
* Swipes come from `mappedInput.wasSwipe()`; the Back edge-swipe is already folded into
  `Button::Back` (`src/MappedInputManager.cpp:284-289,314-325`) — check Back first.
* Do not regress: Power still confirms in the mark sheet; the footer still wins over body
  taps; a long-press still does not deliver a tap.

# M0 — Foundation: build environment, data model, rules, tests

**Worker task brief.** Read `docs/golf/ARCHITECTURE.md` and `docs/golf/CONTRACTS.md`
first; they are authoritative and you do not amend them. The repository root
`AGENTS.md` governs embedded coding standards and is also binding.

## Why this milestone exists

Everything host-testable is pulled into one unit that can be verified without the
device. No hardware is available to you: you can build, you cannot flash. Acceptance
is therefore green builds plus passing host tests plus code review — not a claim that
something works on a panel.

Note this is a refinement of the published plan, which had M0 also standing up an
empty scoring screen. The screen moved to M1 so that M0 stays fully verifiable.

## Deliverables

### 1. Build environment

Add `[env:golf]` to `platformio.ini`, extending `default`, adding
`-DCROSSPOINT_GOLF=1`. Budget: ~8 lines. This is one of the three sanctioned upstream
touchpoints (ARCHITECTURE.md §2).

`pio run -e default` must still build a stock reader with **zero** golf code compiled
in. Verify this rather than assuming it.

### 2. `src/golf/GolfRound.h`

The struct exactly as given in CONTRACTS.md §1. Plain aggregate, no heap, no virtuals.
Add a `static_assert` pinning `sizeof(GolfRound)` so an accidental fattening of the
struct fails the build rather than quietly costing RAM.

### 3. `src/golf/GolfRules.{h,cpp}` — mutation helpers

The **only** sanctioned way to change a counter. Pure functions over `GolfRound&`, no
display dependency, no SD dependency, host-compilable.

Implement the full behaviour table in CONTRACTS.md §2, including:

* incrementing `putts` or `in100` at the ceiling also increments `strokes`;
* decrementing `strokes` below `putts + in100` is **refused** and reports which field
  holds the floor, so the UI can flash it;
* a stroke ceiling of 99;
* no counter goes below 0;
* mutating any counter on an unentered hole marks it entered.

Return a small result type carrying `{ changed, blocked, blockingField }`. Design it so
the caller can render a one-frame inverse flash without re-deriving why it was blocked.

Also provide `GolfField` from CONTRACTS.md §3 and a focus-cycle helper.

### 4. `src/golf/GolfStats.{h,cpp}` — derived figures

Pure functions implementing every row of the CONTRACTS.md §8 table.

**The critical requirement:** every sum is over *entered* holes only
(`strokes[i] != 0`). Including unentered holes reports a better score than was played.
Treat that as the highest-severity bug class in this app and test it directly.

### 5. Host unit tests

Upstream runs host gtest suites under `test/` via CMake/CTest:

```bash
pio run -t unit-tests
```

Add `test/golf_rules/` and `test/golf_stats/` following the structure of an existing
suite (`test/opds_filename/` is a small, clear example). Register them in
`test/CMakeLists.txt`.

Coverage must include, at minimum:

* every row of the invariant table in CONTRACTS.md §2;
* the auto-bump of `strokes` when putts or in100 hit the ceiling;
* the refusal path and the reported blocking field;
* a partially-played round: entered-holes-only sums for score, to-par, thru, and each
  bucket total;
* a round where a middle hole is skipped, confirming it stays excluded;
* the identity `long + putts + in100 == strokes` on every entered hole;
* 9-hole rounds ignoring array entries at and beyond `holeCount`.

## Out of scope for M0

Do not build any of these; they belong to later milestones:

* Any activity or screen, including the scoring screen.
* Persistence, `GolfRoundStore`, `CourseStore`, `RoundArchive`, any file I/O.
* The `HomeActivity.cpp` and `BootActivity.cpp` touchpoints.
* JSON parsing or writing.

Adding them early makes M0 unreviewable and is the most likely way this task fails.

## Acceptance criteria

All must hold, and all are verified by the architect against the code rather than
taken from your report:

1. `pio run -e golf` builds clean.
2. `pio run -e default` builds clean and contains no golf code.
3. `pio run -t unit-tests` passes, including the new suites.
4. `./bin/clang-format-fix -g` leaves the tree unchanged. Never invoke `clang-format`
   directly — the wrapper is the only sanctioned entry point.
5. `pio check -e default` reports no new defects attributable to this change.
6. Exactly two upstream files modified — `platformio.ini` and `test/CMakeLists.txt`
   — each within its line budget. (Corrected: the original brief said one file while
   also requiring suite registration in `test/CMakeLists.txt`. That was contradictory;
   the CMake edit is sanctioned. Append golf suites at the end of the list under a
   `# --- golf (fork) ---` comment.)
7. `GolfRound` matches CONTRACTS.md §1 byte-for-byte in field order, types, and names.
8. No heap allocation in `GolfRules` or `GolfStats`. No `std::string`, no
   `std::vector`, no exceptions.

## What to report back

Keep it short and factual:

* The exact commands you ran and their outcomes. Paste real output for the three
  gates; do not paraphrase.
* `sizeof(GolfRound)` as measured.
* The diff stat against upstream, and confirmation of which upstream files you touched.
* Anything in ARCHITECTURE.md or CONTRACTS.md that was ambiguous, wrong, or that you
  had to work around. This is the most useful thing you can tell me — flag it rather
  than silently choosing an interpretation.
* Anything you could not verify because you lack hardware.

Do not commit. Leave the work in the working tree for review.
